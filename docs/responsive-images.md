# Storefront responsive images

Payload's stored `thumbnail`, `card`, and `hero` URLs now feed a shared `ResponsiveImage` component. It uses native `srcset` width descriptors and layout `sizes` so the browser selects an existing R2 file based on slot width and device pixel density. Actual stored widths are used, not assumptions based on a size name. The original is also a candidate when its known width is larger than the derivatives; a derivative wins when it has the same width as the original. Generated WebP variants are served directly, avoiding an extra Next.js re-encoding step.

Integrated into product cards, grid tiles, the main product gallery, gallery thumbnails, homepage hero images, shared CMS media images, video-reel image posters, quick-shop images and order-tracking thumbnails. Gallery zoom retains the original source for detail. Video playback remains unchanged; video posters use a card-size source because the HTML video poster attribute does not support `srcset`.

The product gallery also provides a 2.5× inline mouse-hover magnifier. It fetches a separate full-resolution layer only on interaction, follows the pointer, and returns to the normal responsive image on pointer exit. Opening the lightbox preserves the full-image view; clicking/tapping its image toggles actual 2.5× magnification. Mouse movement or a one-finger drag pans the magnified area. A drag does not inadvertently trigger tap-to-close zoom. Switching images resets magnification. Escape closes the dialog, arrow keys navigate, focus stays within its controls, and closing restores focus and the previous scroll setting. Zoom-source failures leave the normal image visible. Detail is limited by the resolution of the uploaded source; magnification cannot restore missing pixels.

New cart entries store the thumbnail URL rather than the original where available. Existing browser-saved carts continue to work with their saved URL. Checkout declares its small image slot explicitly. Logo/static assets and payment-proof images are not changed.

URL-only legacy uploads continue through Next Image and its responsive optimization. Missing derivatives fall back to available sizes or the main URL; unpopulated relationship IDs are never treated as image paths. No URLs or filename suffixes are fabricated. GIF/SVG media retain the original source rather than raster variants. This change does not delete any R2 objects, change the media schema, or require environment changes. Old media without generated variants does not magically acquire them; it still uses the legacy fallback until regenerated through a separate maintenance process.

Verification: `npx vitest run --config vitest.config.mts` covers candidate sorting, same-width deduplication, preferred sources, zoom, incomplete metadata, legacy uploads and rendered image attributes. `npx playwright test --config playwright.images.config.ts` also checks actual Chromium `currentSrc` choices for mobile/desktop cards, high-density screens and gallery thumbnails without using the app, database or R2.
