# InstaWorld-supported COD checkout cities

COD checkout now offers only InstaWorld destinations that can be safely associated with the selected province. Prepaid checkout retains the existing Pakistan address catalog. Flat shipping configuration and COD handling charges are unchanged. Existing orders are not rewritten.

The server loads `/cities` using the private `INSTAWORLD_API_KEY` only when COD is enabled. A sanitized city snapshot is cached for one hour in the existing private `nski_commerce_config` collection, with a credential-specific key, refresh lease and failure cooldown shared across Vercel instances. No separate collections, indexes, initialization command or timer is created. Only province, readable city label, exact provider name and checked timestamp reach the browser; no API key, pickup location, legacy credential or account data is exposed.

The provider list has no province metadata. Case/whitespace-normalized **exact** matches to one province in the local catalog are accepted. Unknown spellings, provider-only places and ambiguous same-name towns are excluded rather than assigned to a guessed province. This deliberately shows a safe subset of the full provider list. Adding those excluded places requires reviewed geographic/provider mappings in a future change; do not substitute a nearby city to make booking pass.

The customer sees readable labels but new COD submissions use the provider's exact city name. Switching province clears the city. An unsupported previous selection or a province with no mapped destinations cannot complete COD checkout. If coverage is unavailable, missing credentials or expired during an upstream outage, no broad catalog fallback is used for COD: it stays blocked while non-COD methods remain available. An unexpired cache can be reused during the provider's normal reference-cache window; booking still rechecks the provider list and may fail if coverage changed subsequently.

Server-side `executeCheckout` fetches/reads coverage before entering the order transaction, then validates the province/city pair before any new order or stock write. Existing committed idempotent retries still replay even when coverage is unavailable, so city-list outages do not create duplicate orders or hide saved order identities. The browser list is never trusted as authority. This checkout command restriction does not alter generic admin-created historical orders or retrospectively validate existing order addresses.

Admin shipment booking automatically resolves the stored city against provider names and displays a read-only destination rather than a second full-city dropdown. Old orders with unsupported cities, including spelling aliases, remain blocked pending genuine destination confirmation/address correction. No old Ladhewala Waraich order or other production record was edited.

Deploy the server and checkout together with a valid v2 key and existing commerce initialization. There is no per-visit courier lookup while the shared cache is fresh; the first fill/expired refresh can incur the bounded upstream request. No live authenticated requests were performed during automated tests. Provider HTTP and database cache behavior are mocked, with the optional local Mongo suite given synthetic cached cities rather than a real courier key.
